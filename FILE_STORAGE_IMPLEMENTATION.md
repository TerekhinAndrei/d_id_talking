# Реализация системы загрузки и хранения файлов

## Обзор

Реализована система загрузки и хранения файлов на бэкенде с поддержкой:
- Загрузки изображений (единственный аватар, который заменяется при новой загрузке)
- Загрузки аудио файлов (автоматически удаляются через 10 секунд)
- Публичных URL для доступа к файлам
- Работы на хостинге Render

## Архитектура

### 1. FileStorageService (`app/services/file_storage_service.py`)

Основной сервис для управления файлами:

- **Автоматическая очистка аудио файлов**: Аудио файлы автоматически удаляются через 10 секунд после загрузки
- **Управление аватаром**: Только один файл аватара, который заменяется при новой загрузке
- **Публичные URL**: Генерация публичных ссылок для доступа к файлам
- **Валидация файлов**: Проверка типов и размеров файлов

### 2. API Эндпоинты (`app/api/v1/endpoints/files.py`)

Новые эндпоинты для работы с файлами:

- `POST /api/v1/files/upload/image` - Загрузка изображения (заменяет текущий аватар)
- `POST /api/v1/files/upload/audio` - Загрузка аудио файла (автоматически удаляется через 10 секунд)
- `GET /api/v1/files/avatar` - Получение информации о текущем аватаре
- `GET /api/v1/files/files/{file_id}` - Получение метаданных файла
- `DELETE /api/v1/files/files/{file_id}` - Удаление файла
- `GET /api/v1/files/serve/{file_path}` - Подача файлов для публичного доступа

### 3. Конфигурация

Добавлены новые настройки в `app/core/config.py`:

```python
# File storage settings
UPLOAD_DIR: str = "uploads"
AVATAR_DIR: str = "uploads/avatar"
AUDIO_DIR: str = "uploads/audio"
AUDIO_CLEANUP_DELAY: int = 10  # seconds
BASE_URL: str = "http://localhost:8000"
```

## Функциональность

### Загрузка изображений

1. **Валидация**: Проверяется тип файла (image/jpeg, image/png, image/webp)
2. **Замена**: Старый аватар удаляется, новый сохраняется как `avatar.{extension}`
3. **URL**: Возвращается публичная ссылка на файл

```bash
curl -X POST -F "file=@image.jpg" http://localhost:8000/api/v1/files/upload/image
```

### Загрузка аудио файлов

1. **Валидация**: Проверяется тип файла (audio/mpeg, audio/wav, audio/webm, audio/ogg)
2. **Уникальное имя**: Генерируется уникальное имя файла с UUID
3. **Автоудаление**: Файл автоматически удаляется через 10 секунд
4. **URL**: Возвращается публичная ссылка на файл

```bash
curl -X POST -F "file=@audio.wav;type=audio/wav" http://localhost:8000/api/v1/files/upload/audio
```

### Публичный доступ к файлам

Файлы доступны по URL вида:
- Изображения: `http://localhost:8000/api/v1/files/serve/avatar/avatar.png`
- Аудио: `http://localhost:8000/api/v1/files/serve/audio/{uuid}.wav`

Добавлен новый метод в `ServiceFactory` и `ServiceContainer`:

```python
def get_file_storage_service(self) -> IStorageService:
    """Get enhanced file storage service"""
    return self.factory.get_file_storage_service()
```

### 2. Конфигурация

Обновлен `ConfigurationProvider` для поддержки `file_storage` сервиса:

```python
elif service_name == "file_storage":
    # File storage service is always available for local storage
    return True
```

### 3. Роутинг

Добавлен новый роутер в `app/api/v1/api.py`:

```python
api_router.include_router(files.router, prefix="/files", tags=["files"])
```

## Развертывание на Render

### Переменные окружения

Для бэкенд сервиса на Render необходимо настроить:

```bash
ENVIRONMENT=production
BASE_URL=https://your-app.onrender.com
UPLOAD_DIR=uploads
AVATAR_DIR=uploads/avatar
AUDIO_DIR=uploads/audio
AUDIO_CLEANUP_DELAY=10
```

### Структура папок

```
uploads/
├── avatar/
│   ├── default_avatar.jpg  # Резервный аватар
│   └── avatar.png         # Текущий аватар
└── audio/
    └── {uuid}.wav         # Временные аудио файлы
```

## Совместимость

### Локальная разработка

- Используется локальное файловое хранилище
- URL: `http://localhost:8000/api/v1/files/serve/...`

### Продакшн (Render)

- Используется локальное файловое хранилище на сервере
- URL: `https://your-app.onrender.com/api/v1/files/serve/...`

### Интеграция с D-ID

- Локально: продолжает использовать D-ID для загрузки файлов
- Продакшн: использует новую систему файлового хранилища
