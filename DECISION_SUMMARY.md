# Резюме: Реструктуризация API

## Проблема
Текущая архитектура API имеет серьезные проблемы:
- **Дублирование**: `/generation/voices` и `/streaming/elevenlabs-voices`
- **Смешанная ответственность**: TTS в generation, voice changer в streaming
- **Нелогичная группировка**: upload в streaming, health разбросан
- **Сложная навигация**: сложно найти нужный эндпоинт

## Решение
Полная реструктуризация API с четким разделением по доменам:

### Новая структура:
```
/api/v1/voices/     # Управление голосами
/api/v1/tts/        # Text-to-Speech
/api/v1/video/      # Генерация видео
/api/v1/streaming/  # WebRTC стриминг
/api/v1/storage/    # Управление файлами
/api/v1/tasks/      # Управление задачами
/api/v1/users/      # Управление пользователями
/api/v1/health/     # Мониторинг
```

## Преимущества:
✅ **Четкое разделение ответственности**  
✅ **Устранение дублирования**  
✅ **Логичная группировка**  
✅ **Простота навигации**  
✅ **Масштабируемость**  
✅ **Единообразие**  

## Временные рамки:
- **Общее время**: 10-15 часов
- **Рекомендуемый график**: 2-3 дня
- **Критический путь**: Миграция эндпоинтов + обновление фронтенда

## Риски:
- Временная недоступность API
- Ошибки в обновлении фронтенда
- Потеря данных при миграции

## Митигация:
- Поэтапная миграция
- Резервные копии
- Тщательное тестирование
- План отката

## Альтернативы:
1. **Быстрое исправление** (2-3 часа) - убрать только дублирование
2. **Полная реструктуризация** (10-15 часов) - новая архитектура
3. **Ничего не делать** - оставить как есть

## Рекомендация:
**Полная реструктуризация** - это инвестиция в будущее проекта, которая:
- Упростит разработку новых функций
- Улучшит поддержку кода
- Сделает API более понятным
- Устранит текущие проблемы
